# P0 / P1 实现与验收

更新：2026-11-24。最终验收结果在本轮游戏测试结束后填写。原始规划见 03；当前视觉路线以本文为准。

## 当前路线

- Forge 1.20.1 / 47.4.29，Java 17，Immersive Portals Forge 3.0.7，Cloth Config 11.1.136。
- IP 负责双世界可见性、维度包路由和自然穿越；ROCKET 负责资格、预热预算、Ready、清理及高度视觉。
- 主世界边界默认 Y512，对应太空 Y64。x/z、速度方向和朝向不旋转，连续高度 `H = spaceY + 448`。
- `debugElytraSpaceFlight` 控制当前鞘翅升空入口，未来由火箭实体资格替代。返回和异常脱困不能依赖鞘翅。
- 移除圆球地表和程序化彩色大陆。近地轨道为近乎平直的地形颜色代理；同步轨道为六面像素纹理的方块地球。
- 默认 H1536 开始向高轨道视觉过渡，H2384 完成。它们是压缩的游戏视觉高度，不是现实轨道物理。

## P0：跨界与恢复

服务端每次会话最多额外预热目标半径 2 区块，即 25 个区块；最多 8 个会话。准备窗口 200 tick，确认窗口 100 tick。

客户端 Ready 要求目标 ClientLevel、LevelRenderer、最近目标渲染 pass、25 个完整区块，以及抵达高度附近的非空 section 已编译。已知全空气 section 可直接通过。这只覆盖有界抵达区域，不声称全部远景或全部 GPU 资源就绪。

服务器检查 UUID 会话、配置修订、单调回复序号、来源/目标和区块包络。客户端授权无法选择任意维度或坐标。未 Ready 时保存运动并在边界前等待；超时、取消、退出及配置关闭均释放同一个 IP ChunkLoader 引用并恢复重力。

确认丢失时以服务端实际目标维度为准完成会话，后续无会话快照清理客户端旧准备状态，不重复传送实体。

### 太空返回

- 普通下降也可穿过太空 Y64 返回主世界，角色不必滑翔或装备鞘翅。
- 低于太空 Y40 属于异常恢复：清理会话并返回主世界出生点地表，清零速度和跌落距离。
- 异常恢复在 debug 开关关闭时也运行；太空虚空伤害被拦截。
- 新太空区块的生成地板改为空气。旧存档屏障不批量删除，玩家会在到达旧地板之前离开太空。
- 正常 Y64 返回保留高空坐标映射；主世界仍有普通重力和落地伤害，需要继续滑翔或选择创造模式。

## P1：近轨道与方块地球

`ClientFlightState` 使用服务端同步的映射配置和本地运动插值计算连续高度；服务端每 5 tick 发送权威高度、阶段与会话诊断。

近轨道读取客户端已经加载的主世界列，缓存 64×64 地形颜色图，每 tick 最多处理 128 个样本。它是有限区域的地图代理，不是完整地形 LOD，也不保证每个远景像素与原版方块几何对齐。未加载区域不额外生成区块。

高轨道使用固定的方块地球贴图；来源和再生成方式见 [纹理说明](texture-credits.md)。贴图不代表当前种子的全球地貌。

天空、星空、云和雾随 H 变化。复用 IP 渲染 pass，没有新建递归门户引擎或额外离屏 FBO。动态地形纹理在退出世界时释放。
